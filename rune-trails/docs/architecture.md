# Architecture

Mystic Swirls is an Expo SDK 58 / React Native app with a pure TypeScript puzzle
engine. The single rule that keeps the engine testable is the dependency
direction: lower layers never import upward, and the headless layers never
import UI or native modules.

```
src/app/ (expo-router screens)
   │
src/render/ (Skia canvas, gestures)
   │
src/state/ (zustand session store) ──> src/platform/ (MMKV, haptics)
   │
src/sim/ (turn resolution, effects, hazards, replay)
   │
src/engine/ (board, paths, win, undo, solver, mutations)
   ▲
src/content/ (level schema, parser, validator, loader, level JSON)
```

`src/engine` and `src/content` must stay headless: they may import only each
other and standard JavaScript/TypeScript. ESLint's `no-restricted-imports`
enforces this (see `eslint.config.js`). The engine runs in Vitest, in the Node
level validator, and at runtime.

## Directory layout

| Path | Responsibility |
| --- | --- |
| `src/engine/types.ts` | Board state, cell kinds, elements, mutation records, actions |
| `src/engine/board.ts` | Board factory, indexing, neighbours, cloning |
| `src/engine/path.ts` | Trace start/extension/backtrack, path validation, commit |
| `src/engine/win.ts` | Coverage and solved checks |
| `src/engine/history.ts` | Snapshot undo stack |
| `src/engine/serialize.ts` | JSON-safe state serialization and equality |
| `src/engine/solver.ts` | Time-budgeted depth-first solvability solver |
| `src/engine/mutations.ts` | Serializable mutations with atomic validation |
| `src/sim/effects.ts` | Element effects (fire/water/earth/air) |
| `src/sim/hazard.ts` | `HazardSource` and the scripted implementation |
| `src/sim/resolve.ts` | The fixed-order turn fold and event stream |
| `src/sim/game.ts` | Connect/undo session wrapper |
| `src/sim/replay.ts` | Deterministic action-log replay |
| `src/content/schema.ts` | Level document types, parser, reasons |
| `src/content/validator.ts` | State enumeration + solvability validation |
| `src/content/loader.ts` | Runtime loader that skips invalid levels |
| `src/content/validate-cli.ts` | CI level-validation command |
| `src/content/levels/` | Shipped level documents (`level-01.json` … `level-10.json`) |
| `src/state/sessionLogic.ts` | Pure session rules (ordering, HUD) |
| `src/state/store.ts` | Zustand store wiring engine + platform |
| `src/platform/` | MMKV progress store, haptics, storage adapter |
| `src/render/` | Layout/hit testing, palette, Skia `BoardCanvas` |
| `src/app/` | Expo Router screens and root layout |

## Commands

Run all commands from `rune-trails/`.

```bash
bun install                 # install dependencies
npx expo start              # start the Metro dev server
npx expo start --offline    # start without network access
bun run typecheck           # tsc --noEmit
bun run lint                # expo lint
bun run test                # vitest run
bun run validate:levels     # offline level validation (CI gate)
bun run ci                  # typecheck + lint + tests + level validation
```

Native development builds (a development client is required because Skia,
Reanimated, MMKV, and haptics ship native code):

```bash
npx expo prebuild           # regenerate ios/ and android/
npx expo run:android        # local Android build
npx expo run:ios            # local iOS build (macOS)
```

## Notes

- `ios/` and `android/` are generated by Expo prebuild and are gitignored.
  Configure native behaviour in `app.json`, never by editing those folders.
- Reanimated 4's worklets plugin is added automatically by
  `babel-preset-expo`; `react-native-worklets` is installed. No custom
  `babel.config.js` is needed.
- `GestureHandlerRootView` wraps the router in `src/app/_layout.tsx`, which is
  required for the board's pan gesture.
- The board uses one Skia `Canvas`. Pointer samples stay in shared values; the
  store updates only when a path commits.
